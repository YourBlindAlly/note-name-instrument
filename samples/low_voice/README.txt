LOW VOICE SAMPLE PACK (from low_voice_f__up_and_down_two_octaves-001.flac)

Range: F sharp 2 to C4 (middle C is C4). 27 sung note names.
Naturals: G2 A2 B2 C3 D3 E3 F3 G3 A3 B3 C4.
Sharp names: Fsharp2 Gsharp2 Asharp2 Csharp3 Dsharp3 Fsharp3 Gsharp3 Asharp3.
Flat names: Gflat2 Aflat2 Bflat2 Dflat3 Eflat3 Gflat3 Aflat3 Bflat3.
The sharp names come from the takes sung going up, the flat names from the takes sung going down.
For two notes (Gflat3, Aflat2) the second recorded take was used instead of the first,
because it had a clearly better ending without being meaningfully less steady in pitch.

Two versions of every note, same file names in each folder:
steady: the pitch is held flat at the exact equal temperament note (A = 440). Measured within 0.2 cents.
natural: your own slight pitch movement is kept, and the whole note is shifted to be centered on the note.

Each file is mono, 44.1 kHz, 24 bit WAV, one take. Only the sustained vowel is pitch corrected;
everything from the end of the vowel onward, including any trailing consonant such as the "p" in
"sharp" or "t" in "flat", is left as raw, unprocessed audio straight from the original recording,
since that is the truest version of it and survives better than pushing it through pitch correction.
A short (25 ms) fade is applied only at the very end of the file, so nothing is abruptly cut off.

Remaining known issue: a handful of the sharp and flat endings have a real but very quiet and brief
consonant release in the source recording, close to the room's noise floor. No processing can add
sound that was not captured. If a crisper "p" or "t" matters, a short re-recording of just those
words, sung with a bit more deliberate closure and release on the final consonant, would fix it;
no need to redo the whole pack.

loops.json gives, for each file, the loop start and loop end in sample numbers. A held key plays the
file from the start until the loop end, repeats the section between loop start and loop end while the
key is down, and on release plays the rest of the file after the loop end. The joins are best matched
by waveform, and a 20 millisecond crossfade is recommended.
